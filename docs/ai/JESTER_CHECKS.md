# Jester Checks — HiveMap

Use this for architecture, API, storage, async, agent-mediated workflows, and anything that could become accidental complexity.

## Core Questions

- Is this creating a diagram editor instead of an agent-mediated concept map?
- Is UI layout leaking into semantic truth?
- Is a speculative agent inference being stored as confirmed truth?
- Is a projection being treated as the graph model?
- Is a custom category bypassing the category catalog?
- Is a POC shortcut becoming 1.0 architecture without decision evidence?
- Is a flat map being used where overview/dive-in is required?
- Is the agent allowed to mutate data without clear capture policy?
- Are failures explicit enough for a human to correct the model?
- Does this create hidden coupling to HiveMind?

## Verdicts

- `Green`: no obvious concern.
- `Yellow`: concern exists and is bounded.
- `Red`: do not proceed without fixing the model/contract.
- `Siren`: stop; confirmed truth, security, governance, or graph integrity is at risk.

## Required Output

- Verdict.
- Top risks.
- Required proof/tests.
- Safer alternative if obvious.
